runtime polymorphism or dynamic method dispatch.
## Parent p2 = new Child(child, parent);
p2.parent();
p2.child();

# ⚙️ What’s Actually Happening Here

When you write:
Parent p2 = new Child(...);


you are doing upcasting —
i.e., you are storing a Child object inside a Parent reference.

🧠 Important Rule

In Java, the reference type (on the left side of =) decides what methods and variables you can access at compile time.
The actual object type (on the right side) decides which implementation runs at runtime.

🧩 Step-by-step
1️⃣ Compile-Time Behavior (Reference Type Check)

p2 is of type Parent
So the compiler only lets you access methods declared in Parent (or inherited by Parent).

That means:
✅ p2.parent() → allowed
❌ p2.child() → compile-time error

Even though the object is of type Child, the compiler looks only at the reference type (Parent), not the object type.

2️⃣ Runtime Behavior (Dynamic Dispatch)

If the method parent() is overridden in Child,
then at runtime, the JVM calls the Child version — not the Parent version.

## That’s runtime polymorphism or dynamic method dispatch.

✅ Example
class Parent {
    void parent() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    void parent() {
        System.out.println("Child overridden method");
    }

    void child() {
        System.out.println("Child-only method");
    }
}

public class Main {
    public static void main(String[] args) {
        Parent p2 = new Child();
        p2.parent();  // ✅ Calls Child's version at runtime
        // p2.child(); // ❌ Compile-time error
    }
}

🧾 Output:
Child overridden method

💬 But Why Not Access child()?

Because the compiler only checks the reference type,
and the reference type Parent doesn’t know that its object is a Child.

That’s why this fails:

p2.child(); // ❌ Compile-time error: cannot find symbol

✅ How to Access child() Then?

If you are sure the object is actually a Child, you can downcast it:

Child c1 = (Child)p2;  // safe if p2 is really a Child object
c1.child();            // ✅ Works now

Output:
Child-only method

⚠️ But be careful!

If you downcast when the object isn’t really a Child,
you’ll get a ClassCastException at runtime:

Parent p3 = new Parent();
Child c2 = (Child)p3; // ❌ runtime error

🧩 Summary Table
Expression	Meaning	Allowed?	What Runs
Parent p = new Parent();	Normal parent object	✅	Parent’s methods
Child c = new Child();	Normal child object	✅	Child’s methods
Parent p = new Child();	Upcasting	✅	Child’s overridden methods only
Child c = new Parent();	Downcasting automatically	❌	Compile-time error
(Child)p.parent();	Manual downcasting	✅ (if actually a Child)	Child’s methods accessible
🧠 One-Line Concept:

You can only call methods available in the reference type,
but at runtime, the object type decides which version executes.
